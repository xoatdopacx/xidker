# xidker — web bán source code portfolio

Multilingual (33 languages) sales page, styled and animated like a pixel-art game road map, that sells portfolio website source code (not landing-page services). Buyers create an account (email confirmed with an emailed code, common email providers only), place an order and pay by VietQR bank transfer; the admin confirms each payment by hand in the dashboard, then the buyer downloads the source zip from the order page. Contact email: hello@idkworkshop.com.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server
- `pnpm --filter @workspace/web-landing run dev` — run the landing page (served at `/`)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL`, `SESSION_SECRET` (keys every stored hash), `ADMIN_EMAIL` (the account registered with this address is the admin). Email goes out through the Gmail integration. `ADMIN_TOKEN`, `WHOP_COMPANY_ID` and `WHOP_PRODUCT_ID` are no longer read.
- Nobody can order until the admin has registered with `ADMIN_EMAIL` and filled in the bank account in the dashboard (Cài đặt): `POST /api/orders` answers 503 and buyers see "the store is updating its payment details". The workspace and the published site have separate databases, so each needs its own admin account and bank details.
- Landing tests: build with `PORT=5173 BASE_PATH=/ NODE_ENV=production pnpm --filter @workspace/web-landing run build`, then `node --test artifacts/web-landing/tests/*.test.mjs`; `node artifacts/web-landing/tests/browser-smoke.mjs` drives chromium against the running dev workflows.
- `MAIL_TEST_OUTBOX=<file>` makes a test API server append its emails to that file (JSON lines) instead of sending them. Never set it on the published app.
- `whop-api.mjs` / `whop-mcp.mjs` in the project root only reach the old Whop catalog; the site no longer uses Whop.

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5; payment QR: VietQR text built in `vietqr.ts`, drawn as SVG with `qrcode`
- DB: PostgreSQL + Drizzle ORM
- Frontend: React + Vite, Tailwind, wouter; pixel art is inline SVG (no WebGL). The only bitmaps are the user's own cat memes turned into pixel art (small PNGs in `src/assets/`, drawn with `.pixel`; the cat rider is a 6-frame strip) and the sample pictures
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)

## Architecture decisions

- Accounts: email + password (at least 8 characters). A new address must use one of the common providers listed in the dashboard (Cài đặt; throwaway inbox services are kept out by not being listed) or be `ADMIN_EMAIL`. The email is confirmed with a 6-digit code before the account can order or chat. A code only works in the browser that asked for it (httpOnly cookie), allows 5 tries, and never appears in the email subject. Registering an address that already has an account answers exactly like a new one and emails the owner a sign-in link instead. Password reset is by emailed code and signs every browser out. Failed attempts are counted in the database (works across server instances).
- Admin: the `ADMIN_EMAIL` account signs in on the same form, always needs an emailed code as well, and lands on `/quan-tri`. Buyers get 401 from every `/admin/*` route. Admin replies in the chat use their own input schema (`AdminMessageInput`, no language field).
- Price list: `store_packages`, edited in the dashboard (Sản phẩm & giá): Vietnamese and English text, VND price, optional approximate USD price, and switches for visible, recommended and "buyer picks a sample". The default three packages are seeded once (a flag in `site_settings`), so a deleted one does not come back. A package with orders can only be hidden. The site picks up changes within 30s (in-memory cache; a save clears it on the server it hits).
- Package text per language: Vietnamese and English as written in the dashboard; the other languages use the built-in translations in `packageTranslations.ts` while the English text still equals the translation's `source`, else English. The dashboard shows which state each package is in; after rewording a package in English, refresh `packageTranslations.ts`.
- Orders: code `XID` + 6 characters, which is also the transfer memo. The order page shows a VietQR code (every Vietnamese banking app fills in bank, account, amount and memo from it) plus the details to copy. The buyer can press "Tôi đã chuyển khoản" or cancel; the admin marks the order paid (the buyer gets an email), back to unpaid, or cancelled. At most 3 unpaid orders per account and 10 orders a day. Prices are charged in VND; other languages also show the approximate USD price.
- Delivery: a paid order downloads the zip attached to that order, else the current zip of the picked sample (newer uploads reach earlier buyers). Downloads need the buyer's own signed-in account; the zips are never public. Without a file, the order page and paid email point the buyer to the chat.
- Email links (order page, sign-in) use the request's Origin/Referer only when the host is one of the app's own domains (`REPLIT_DOMAINS`/`REPLIT_DEV_DOMAIN`), so a forged header cannot point them elsewhere. They carry `?lang=<email language>`.
- Language: `GET /api/packages?lang=<code>` (33 codes) localizes package text server-side. Home translations use stable `/<code>/` URLs; `/` is the English default (`x-default`). The home URL wins over stored/browser preferences so crawlers and visitors see the same language. Pages without a language in the path (sign-in, account, orders) use `?lang=`, then the saved choice, then the browser. A language URL (`/vi/` or `?lang=`) is saved as the visitor's choice, server-rendered home pages included. Legacy home `?lang=` links are normalized in the browser.
- Locale SEO: the Vite plugin generates 33 localized HTML shells with self-canonical, reciprocal hreflang, crawlable language links and social metadata. `seo/site.ts` uses the confirmed production origin; set build-time `SEO_SITE_ORIGIN` when moving domains. `public/share-card.png` is the 1200×630 preview (editable source in `seo/share-card.svg`). Account, order and dashboard pages are noindex.
- Server rendering: dev and production both run `seo/server.mjs`, which renders the sales page with live prices in the HTML. It reads the catalog from the API through `localhost:80` in dev and directly on the API's own port (8080) in production. If the catalog is down or slower than 3s, the page still answers 200 without prices and the browser loads them. Never let `/` depend on the API, because the publish health check calls `/`.
- Template demos: `seo/server.mjs` serves `public/demo/<slug>/` with a CSP of their own (`sandbox`, so a demo runs in an opaque origin and can never act with the visitor's sign-in; outside pictures, fonts and 3D files allowed), `Access-Control-Allow-Origin: *` (module scripts from a `null` origin are CORS requests) and noindex. Exception in development only: opened through the private workspace URL, a demo also gets `allow-same-origin`, because the browser would leave the Replit sign-in cookie off the demo's own files and they would come back as Replit's login page. Jack and Mainframe are Vite apps built with `base: "./"` and copied in from their `dist/`; Reelmark and Iris are single HTML files; Michelle, Kin, Rowan, Noa and Plinth are single HTML files plus an `assets/` folder of pictures, copied as is (the READMEs stay out of the demo copy). Rowan (developer), Noa (film photographer) and Plinth (architecture studio) are original designs made for the store, with generated pictures and fictional names. idk portfolio (slug `idk-portfolio`) is the user's own studio page (their copy, name and hello@idkworkshop.com) around a 3D ocean written here from scratch (three.js r186 + Lenis in `vendor/`, fonts bundled, ES modules plus an import map, so it needs a web server: `python3 serve.py` in the zip); its demo copy leaves out `serve.py` and the READMEs.
- Template files: each zip has one top folder `<slug>/` and no `node_modules` or `dist`; previews are `<slug>.webp` plus a 640×800 `<slug>-thumb.webp` of the top. Each template becomes an ordinary sample the first time a server that has it starts on a database (picture, demo link, source zip); `site_settings.templates_seeded` lists the slugs already added (the legacy value `true` means the first four), so a template the admin deleted never comes back and a newly shipped one is added once. After that the admin owns them.
- Addresses carry no `#section`: nav links scroll without touching the URL, and an old `/vi#hoi-dap` link lands on the section and then drops the hash.
- Security headers: the page server (`seo/server.mjs`) sends CSP, X-Frame-Options, COOP and CORP on the published site only, because the workspace preview frames the dev server; nosniff, Referrer-Policy and Permissions-Policy apply everywhere. Each page gets a fresh CSP nonce on the shell's own `<script>` tags, and inline event handlers in `index.html` are allowed by hash automatically. Any new outside script, stylesheet, font, image host, API call or iframe must be added to `pagePolicy`, or browsers block it on the live site only. COEP stays off (it would block Google Fonts). The `GAESA` cookie and `Server: Google Frontend` come from the hosting and cannot be changed. The API sets its own headers with helmet; POSTs from another origin get 403.
- Support chat is for signed-in accounts that have placed an order here (or bought on Whop before), so the inbox only holds real customers.
- Source samples: a package with "buyer picks a sample" opens the sample picker before ordering. `GET /api/packages` reports `pickSample: false` while no sample is visible (or the database is down), so the picker only appears when there is something to pick. The order stores the sample id and a name snapshot (kept after a rename or delete). Sample names are shown as written in every language.
- Sample pictures are shrunk in the admin's browser (full picture at most 1600 px wide, plus a 640×800 preview of its top), sent straight to App Storage through a signed upload link (so the `/quan-tri` CSP allows `https://storage.googleapis.com` in `connect-src`, and only there), and served same-origin from `/api/storage/objects/...` only once they belong to a saved sample (cached as immutable). Deleting a sample or removing a picture deletes the files.
- Chat updates by polling the database (customer panel every 3s while open, admin list 5s, admin thread 3s), because the app runs on autoscale and in-memory state would split across instances.
- Chat translation (`artifacts/api-server/src/lib/chatTranslate.ts`, Replit AI Integrations → OpenAI; no API key, usage is billed to Replit credits): customer messages get a Vietnamese translation when the admin's inbox asks for it (on opening a thread, never during the customer's send). Admin replies are translated before saving into the language of the customer's newest message with a known language, else the conversation's site language. If translating fails, the reply is saved as written, the customer reads the Vietnamese and the admin sees "Dịch lại". The conversation list keeps the original text.

## Product

- Sales page in 33 languages (pixel globe picker in the header and footer; Arabic, Persian, Hebrew and Urdu read right to left): pixel-art road-map world where scrolling walks a character from START to a trophy, packages with VND prices, FAQ, contact email.
- Buying: a package with a sample choice first opens the sample picker (pictures, full screenshots, live demo, pick one). Signed out, the buyer goes to sign-up (or sign-in) with the order kept, confirms the email, and the order is placed right after. The pricing grid adapts to 1–5+ packages.
- `/don-hang/<code>`: QR and transfer details while unpaid; a pixel "we are checking" road scene after "Tôi đã chuyển khoản"; when paid, the user's fat pixel cat hopping among sparkles and the download button; a cancelled order shows the user's pixel cat holding an empty wallet. `/tai-khoan` lists the account's orders and opens the support chat.
- Unknown addresses get a 404 page with the user's other two cat memes: in the card, a man riding a giant cat gallops past a signpost on the road; outside it, a meadow of little road-world places, with the cat asleep in a Minecraft bed in the bottom-left corner of the page (under the card on phones and tablets).
- Refund policy (set by the user, 2026-10-15): refunds only while the order has not been confirmed; once the source has been sent and the support chat is closed, every refund method is void. It is shown in all 33 languages as the last FAQ item and as a "please note" line in the note under the pricing cards; `marketing/policy/refund-policy.html` renders the same text to a PDF. Change them together.
- Dashboard `/quan-tri` (Vietnamese only): Tổng quan (revenue today, this month and in total, orders waiting for a transfer check, customers, unread messages, 14-day revenue chart, newest orders, a line saying what needs doing now), Đơn hàng (filter and search; per order: mark paid / unpaid / cancelled, attach a zip for that order, a note shown to the buyer, a private note), Khách hàng (search, lock or unlock an account), Sản phẩm & giá, Mẫu source (pictures, demo link and source zip per sample; upload, reorder, hide/show, delete), Tin nhắn (inbox with a Vietnamese line under every customer message and the translation each reply was sent with), Cài đặt (bank account for the QR, allowed email providers).

## User preferences

- Talks in Vietnamese; reply in plain Vietnamese without technical jargon.
- Use SVG icons, no emoji anywhere in the UI. Motion and look follow the user's pixel-art game "ROAD MAP" reference (attached_assets/__1791889422870.jpg); this replaced the earlier artsy 3D sculpture direction.
- Vietnamese copy must be plain, natural everyday Vietnamese; the user rejected the poetic headline "Trang bán hàng khách dừng lại để ngắm."
- Brand is "xidker" (lowercase). The only real contact detail is hello@idkworkshop.com; do not add phone numbers or addresses unless the user provides them.
- The product is portfolio source code. Packages are managed by the user from `/quan-tri` (see the pricing-rules memory for the agreed contents of the current three). Payment is VietQR bank transfer confirmed by the admin by hand, and every buyer must have a confirmed account (user's choice, 2026-10-22; Whop was removed from checkout). The six templates are sold as source code only (never the prompts).
- No invented social proof (customer names, testimonials, counts, statistics).

## Gotchas

- `lib/api-client-react/tsconfig.json` needs `"dom.iterable"` in `lib` or the generated client fails typecheck (`Headers.entries`).
- The dev source-mapping plugin cannot parse JSX type arguments (`<Route<T> ...>`); the dev server then fails on that file. Type the props instead.
- `vite.config.ts` pins `optimizeDeps.entries` to `index.html` (otherwise Vite scans the demo HTML in `public/demo`), and the server-rendering build skips copying `public/`.
- Template `package-lock.json` files must point at `registry.npmjs.org`; installs in this workspace go through Replit's internal npm mirror, whose URLs buyers cannot reach.
- The road on the home page is measured from the `[data-road]` anchors in the page layout. Any interaction that changes page height (e.g. an expanding FAQ) reshapes and stretches the road, so interactive parts must keep a fixed height. Switching language is the only expected exception.
- Pixelify Sans draws 2 like Z/8 and 5 like S. Digits use `.font-num` (Silkscreen); Pixelify Sans is for letters only, and it is not used for Vietnamese text.
- Card "pixel build" reveals keep their state in DOM data attributes (`data-rv`, `data-built`) and use one shared scroll check, not IntersectionObserver, so cards skipped by a fast jump finish instantly instead of staying hidden. A remounted card builds again, so lists must not remount on re-render (the package list keeps previous data while the other language loads).
- The price size on each package card follows the card width with a cap, so long VND prices fit tablet cards without changing card height.
- `.tile` (unlayered CSS) sets `position: relative`, which beats Tailwind's `fixed`; a `.tile` element that must be fixed needs `fixed!` (the language panel opened off-screen until this was fixed).
- New UI text goes into `vi.json` and `en.json` first; other locales fall back to English key by key until translated. Prices always use Latin digits (`numLocale`), because the number font only has those.
- Right-to-left languages flip text and arrows only; the road, the walking character and the `[data-road]` geometry are never mirrored.
- In-page `#` links are intercepted by the full-screen scene transition, which scrolls instantly with a 64px header offset. Keep section anchors on `id`s and give the transition a destination label for any new jump target.
- A language switch blocks the page for several hundred ms (re-render, text layout, font swap; worst for Chinese/Japanese/Korean). The loading card's bar, walker and percentage are queued up front as browser (compositor) animations so they keep moving through that; do not drive them with JS timers. The new language's font stylesheet is added only after the screen is covered, because adding a stylesheet restyles the whole page and would stall the cover animation.
- Transition and card-build canvases are reused from a pool; creating canvases costs more than drawing into them.
- Inside Radix dialogs (the sample picker), show errors inline, not as toasts: toasts sit under the dialog backdrop.
